# Подготовка к контрольной работе

## Когда я выберу rebase, а когда merge? Почему?
Rebase выберу для своей ещё не опубликованной ветки: перенесу коммиты на актуальный main и получу линейную историю. Merge выберу для интеграции общей ветки, чтобы сохранить исходные коммиты и факт параллельной разработки.

## Что произойдёт при rebase публичной ветки?
Переписываемые коммиты получат новые хеши. У коллег останется прежняя история, возникнет расхождение, возможны повторные коммиты и конфликты. Поэтому общие ветки не переписываю без согласования, а ошибочные опубликованные изменения отменяю через revert.

## Зачем нужен multi-remote?
Несколько remote нужны для резервного зеркала, работы с fork и upstream, миграции между площадками и передачи кода разным командам. В этой работе основной репозиторий и зеркало размещены на GitHub; два push-URL origin позволяют отправлять изменения одной командой. Каждый push нужно проверять: отправка на серверы не является общей атомарной операцией.
