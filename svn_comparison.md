# Сравнение Git и SVN

## 1. Почему ветвление в Git считается дешёвым?

В Git ветка — небольшой указатель на коммит.
Создание ветки выполняется локально без копирования всех файлов.

В SVN ветки представлены копиями каталогов в репозитории.
Однако SVN использует cheap copies: создание ветки на сервере
тоже не требует физического копирования всех данных.
Поэтому утверждение, что ветвление в SVN всегда дорогое, неточно.
Основное различие — архитектура и зависимость операций
с центральным репозиторием от доступа к нему.

## 2. Можно ли в SVN сделать коммит без интернета?

Для коммита нужен доступ к репозиторию: новая ревизия сохраняется
непосредственно в нём. Если удалённый сервер недоступен,
коммит выполнить нельзя.

Сам интернет не обязателен: репозиторий может находиться
в локальной сети или на том же компьютере.
В Git коммиты сохраняются локально и отправляются отдельно.

## 3. Когда SVN может быть предпочтительнее?

- В существующем проекте с настроенными процессами и интеграциями SVN.
- Когда нужны централизованные права доступа к отдельным каталогам.
- При работе с плохо сливаемыми бинарными файлами,
для которых команда использует блокировки.

Выбор зависит от требований проекта и организации работы команды.
